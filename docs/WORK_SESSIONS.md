# Work Session Management — My Work Planner

This guide describes the domain model, database rules, and user workflows for **Work Sessions** in *My Work Planner*.

---

## 1. Domain Overview

A work session represents a focused block of time dedicated to a task or project. My Work Planner supports two distinct session sources:

1. **Automatic Sessions (`entry_type = 'automatic'` or `'timer'`)**:
   - Generated by the live count-up timer.
   - Bounded by concrete server-derived `started_at` and `ended_at` timestamps.
   - Committed automatically on **Pause**, **Stop**, **Save & Switch**, or **Complete Task**.
   - Minimum duration guaranteed to be strictly positive (> 0 seconds). Empty or zero-length segments are never persisted.
2. **Manual Entries (`entry_type = 'manual'`)**:
   - Created manually via the **Add Manual Time Entry** drawer/modal.
   - Supports logging retrospective work by specifying either:
     - **Duration Mode**: Positive whole minutes (e.g. 45m).
     - **Time Range Mode**: Explicit `startTime` and `endTime` (e.g. 10:00 to 11:15).
   - Can include optional notes describing the work completed.
   - Does NOT disrupt the global active timer.

---

## 2. Multi-Session Aggregation per Task

A task can accrue any number of working sessions across multiple days, weeks, or individual focus sprints.

### Example Session Breakdown:
| Session | Entry Type | Start | End | Duration | Notes |
|---|---|---|---|---|---|
| Session 1 | Automatic | 09:00 AM | 09:45 AM | 45m | Focus sprint #1 |
| Session 2 | Automatic | 11:15 AM | 11:45 AM | 30m | Focus sprint #2 |
| Session 3 | Manual | 02:00 PM | 02:20 PM | 20m | Client demo call |
| **Total Saved Work Time** | — | — | — | **1h 35m** (5,700s) | — |

If a focus timer is currently **running** on this task (e.g., elapsed 10m):
- `Current Active Session`: **10m** (600s).
- `Saved Work Time`: **1h 35m** (5,700s).
- `Live Actual Time`: **1h 45m** (6,300s).

## 3. Data Integrity & Task Deletion Safety

A core requirement of personal time tracking is that productivity records should outlive individual task lifecycles:

```sql
constraint work_sessions_task_user_fkey foreign key (task_id, user_id)
  references public.tasks(id, user_id) on delete set null
```

- When a user deletes a task, PostgreSQL automatically sets `work_sessions.task_id = NULL`.
- The duration and date logs remain intact in `work_sessions` and continue contributing to daily, weekly, and monthly totals on the **Reports** and **Time Tracker** screens.
- Automatic sessions cannot be tampered with or overwritten by manual entries.

## 4. Manual Entry Validation Rules

PRD Section 9.5 and `validateManualTimeEntry` in `timeMath.ts` enforce:

1. **Task Association**: Must select a valid task belonging to the authenticated user.
2. **Work Date**: Required date string (defaults to today's local date `YYYY-MM-DD`).
3. **Duration Mode**:
   - Must be a positive integer > 0.
   - Upper bound: At most 1,440 minutes (24 hours).
4. **Range Mode**:
   - Valid `HH:mm` format for start and end times.
   - `endTime` must be strictly later than `startTime`.
   - Computed duration in seconds: `(endMinutes - startMinutes) * 60`.
